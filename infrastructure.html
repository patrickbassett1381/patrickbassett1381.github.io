U-101 · LIVE

RunsEvery hour, in Google's cloud

Google Apps ScriptJavaScriptCanvas REST APIGoogle DriveGit / GitHub

bCourses → Google Drive sync

Checks all my courses every hour, files each new handout, slide deck and assignment into the right Drive folder, and keeps a small tablet folder of Word and PowerPoint files converted to PDF so my reMarkable can open them.

Problem

Four courses, four professors, four ways of posting files. Some posted slides inside lecture pages instead of the Files tab.

Solution

Two filing modes (mirror the professor's folders, or read lecture pages and modules), a keyword fallback with an "Unsorted" folder, and a state file so nothing downloads twice.

Result

~380 course files filed automatically in the first module, each within the hour. That replaced ~3 hours a week of checking four courses and filing by hand.

  • A nightly notes queue: the list of notes no Concept Log has read yet, for the study system.
  • One summary email a night, and only when something new arrived.
  • Each step runs even if another fails, and any failure still triggers an error email.
  • New term = new config entries, not new code. Courses drop off after their final.

Design decisionThe university blocks the Google Cloud setup a normal Python script needs. Instead of switching to a personal account, I moved the whole tool into Apps Script, which runs inside Google as me. Constraint first, then the tool.

Human in the loopMy reMarkable can only pull files from Drive by hand, so the last step is mine: I import that day's slides before class. The script's job is to make that a two-tap step.

U-102 · LIVE

RunsNightly, 8:52 PM

Claude scheduled taskMCP connectorsGoogle Drive

Notes sorter

Every night, takes my class and meeting notes from that day and files each one as a Google Doc in the right place: a lecture goes to that course's notes, a group-project meeting to the project folder, a coffee chat to recruiting, a club meeting to clubs.

  • Written routing rules, with tie-breakers. A club event about jobs goes to recruiting; one about the club itself goes to clubs.
  • Looks back seven days, so a missed night is caught by the next run.
  • Unclear notes go to a "Needs Review" folder for me, never into a guess.
  • Never moves, edits or deletes anything already in Drive.

Design decisionEach filed Doc carries the note's unique ID in its header. Before filing, the job searches Drive for that ID, so duplicates are impossible without keeping a separate log file. The same ID later tells the Concept Log digest which classes it has already read.

U-103 · LIVE

UpdatedEach 7-week term

Google Docs

Course Index

One Google Doc holds every fact about every course: folder locations, class times, exam dates and format, the AI policy, where each professor posts slides, and my role on each team. Every skill and the sync script read it; none keeps its own copy.

Design decisionA few lines in the Index follow a fixed format so the script can read them too. That turns "set up a new term" into editing one document, with no code change.

Drive inbox

One drop folder for everything that doesn't come from bCourses: saved web PDFs, transcripts, Word files. On request, Claude proposes where each file goes as a table, and moves them after I say OK.

Design decisionApproval first until the rules have held for two weeks of real sorts; then decide whether it earns a nightly schedule. A file with the same name and size as one already in the destination is flagged as a likely duplicate, not moved.

U-106 · LIVE

Weekly health audit

Automation fails quietly, so once a week a read-only check confirms the sorter ran, every note was filed exactly once (flagging MISSING or DUPLICATE), and nothing has sat in the inbox or review folder for more than seven days.

Design decisionThe audit rides along with the Sunday review I already read, instead of sending a separate report I would learn to ignore.

Metrics are conservative estimates; method on request.

How I keep it maintainable

Roadmap and decision log

Every design choice above is recorded with its date and reason, and every failure becomes a one-line lesson. When something breaks months later, the log says why it was built that way.

IDs, not names

Folders are referenced by permanent ID, so renaming or moving a folder never breaks routing.

Code lives in git

Local clones stay outside synced drives, because Drive syncing a git folder corrupts it. Tokens and personal data never get committed.

One writer per file

Each file has exactly one job allowed to write it. The tablet folder belongs to the script; prep sheets belong to the study system.

Public pages only

The sync reads only what students can see on bCourses, never hidden pages.
