bCourses → Google Drive sync

A script that checks all my courses every hour, files each new handout, slide deck and assignment into the right Drive folder, and keeps a small tablet folder of Word and PowerPoint files converted to PDF so my reMarkable can open them.

Problem

Four courses, four professors, four different ways of posting files. Some posted slides inside lecture pages instead of the Files tab.

Solution

Two classification modes (mirror the professor's folders, or read lecture pages and modules), a state file so nothing downloads twice, and one daily summary email.

Result

~380 course files filed automatically in the first module, each within the hour. That replaced ~3 hours a week of checking four courses and filing by hand.

Design decisionThe university blocks the Google Cloud setup a normal Python script needs. Instead of switching to a personal account, I moved the whole tool into Apps Script, which runs inside Google as me. Constraint first, then the tool.

Human in the loopMy reMarkable can only pull files from Drive by hand, so the last step is mine: I import that day's slides before class. The script's job is to make that a two-tap step by putting every file where I expect it.

MBA study system

An AI pipeline that sorts my class notes every night, then digests them, along with the handwritten notes I take on lecture slides, into one running "Concept Log" per course. The same logs feed my night-before class prep sheets and my exam cheat sheets.

Problem

My notes were scattered across typed files, a handwriting tablet and class recordings. Nothing connected them at exam time.

Solution

A nightly sorter with written routing rules. A digest that reads my ink on the slides I annotate in class, plus only what the professor flagged as testable in recordings. Reusable skills turn the logs into prep and cheat sheets.

Result

One source of truth per course. The AI reads only the moments professors flag as testable, a small slice of each transcript, which keeps the recording step cheap.

Design decisionA cheap script gathers and filters; the AI only judges. The sync script builds a nightly queue of new notes, so the AI no longer opens every course log just to check what is missing.

Coffee-chat prep

A booking page for recruiting conversations, plus a morning job that researches each person I'm meeting and puts a one-page brief on my calendar five minutes before we talk.

Problem

Recruiting means many short conversations. I was relying on memory to keep track of who said what and what I meant to ask, and prep often got skipped for people I hadn't met yet.

Solution

Guests pick Zoom or in person. At 6:45 AM a task reads their booking answers, recent news, past emails and notes, then writes the brief: top three points, a 30-second intro, a closing ask.

Result

~30 contacts each have a one-page brief: our past conversations, my open follow-ups and what I want to ask. Every chat starts where the last one left off.

Design decisionOne run a day instead of hourly. A 12-hour booking notice and a 6 PM cutoff mean the day's chats are fixed by early morning, so a single run covers everything. It never edits the guest's invite or sends email on my behalf.

Operating rules

How I build

The same habits from strategy work, applied to code and AI.

One source of truth

Every fact lives in exactly one place. Other tools read it; they never keep a second copy.

Scripts gather, AI judges

Deterministic code does the filtering for free. The model is used only where judgment is needed, which keeps cost and errors down.

Guardrails before automation

Nothing I build deletes files or messages people on its own. Uncertain items go to a review folder for me.

Built to last two years

Folders are referenced by ID, not name, and new terms plug in through one index file instead of code changes.
